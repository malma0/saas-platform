# TT-Service — Статус проекта

> Система управления клубом настольного тенниса
> Дата отчёта: **22.06.2026**

---

## 1. Что это за проект

Мульти-тенант платформа для управления клубом настольного тенниса. Состоит из четырёх «поверхностей»:

| # | Поверхность | Назначение |
|---|-------------|------------|
| 1 | **Backend-ядро** (Laravel) | Бизнес-логика: брони, расписание, платежи, CRM, отчёты |
| 2 | **Админка** (MoonShine) | Управление клубом для администраторов |
| 3 | **Client API** (REST v1, Sanctum) | Бэкенд под мобильное приложение |
| 4 | **Analyzer** (Python + БД) | Анализатор реальной занятости столов (компьютерное зрение) |
| 5 | **Публичный сайт** (Blade) | Витрина клуба + онлайн-бронирование |
| 6 | **Flutter-приложение** | Мобильный клиент (планируется) |

---

## 2. Готовность в процентах

### Общая: **≈ 45%** (весь продукт) / **≈ 60%** (то, что можно показать сейчас)

Фундамент (невидимая, самая сложная часть) почти готов и покрыт тестами. Видимые заказчику «витрины» — в начале пути.

| Часть | Готовность | Статус |

## 3. Что СДЕЛАНО

### Backend-ядро (11 доменов, DDD-архитектура)

- **Booking** — движок броней: создание с защитой от гонок (`SELECT FOR UPDATE`), конфликт-чек пересечений, holds (временная блокировка слота), перенос, отмена, подтверждение, кэш доступности
- **Scheduling** — шаблоны расписаний, регулярные занятия, материализация сессий
- **Facilities** — филиалы, залы, столы, иерархия ресурсов (closure-table), рабочие часы
- **Services** — услуги (аренда стола/зала, индивидуальная тренировка)
- **Payments** — платежи (доменная логика)
- **Crm** — клиентская база
- **Reports** — отчёты с выгрузкой CSV/XLSX
- **Identity** — пользователи, RBAC (superadmin / owner / admin)
- **Attendance** — учёт посещаемости
- **ClubCore** — ядро клуба
- **Analyzer** — контракт интеграции с Python-анализатором

**Инфраструктура:**
- Мульти-тенантность (изоляция по `club_id` через глобальный scope)
- 48 миграций БД (PostgreSQL)
- **17 наборов feature-тестов** (Booking, Payments, Scheduling, Multi-tenancy, RBAC и др.)

### Админка MoonShine

- 11 ресурсов: Booking, Branch, Club, Venue, Hall, Resource, ServiceOffering, Client, Staff, пользователи и роли
- Управление бронями: создание, подтверждение, перенос, оплата, отметка посещения, отмена
- RBAC: разграничение доступа по ролям

### Client API (REST v1, Sanctum)

15 эндпоинтов: регистрация/логин, расписание, услуги, профиль, holds, CRUD броней.

### Публичный сайт

3 страницы, подключённые к реальной БД: главная, расписание (`/schedule`), партнёры (`/partners`).

## 5. Что ОСТАЛОСЬ — приоритеты

### 🥇 Приоритет 1 — Analyzer (с 10%)
Главная уникальная фича. Python-анализатор пишет реальную занятость столов в `table_occupancy_sessions`, Laravel сравнивает «забронировано vs реально занято» и показывает расхождения (стол простаивает при брони / занят без брони). Контракт уже заложен — нужны: логика сравнения, отчёт/виджет в админке, сам Python-сервис.

### 🥈 Приоритет 2 — Публичный сайт (с 35%)
- Бронирование прямо с сайта с записью в БД (закрыть петлю клиент → БД → админка)
- Оживить неактивные кнопки навигации: Клуб, Турниры, Тренеры, Контакты
- Блок тренеров подтянуть из модели Staff

### 🥉 Приоритет 3 — Flutter-приложение (с 0%)
API готов — поднять каркас: экраны логина, расписания, бронирования.

### Приоритет 4 — Платёжный шлюз
Подключить реальную оплату (ЮKassa / Сбер) к существующему домену Payments. Нужны ключи мерчанта.
